# 機能設計書

## プロジェクト方針

### コアコンセプト
**「5分で始められる、誰でも使えるシフト管理」**

### 差別化戦略
- ❌ AI自動化などの高度機能は追わない
- ✅ **圧倒的なシンプルさ**で勝負
- ✅ **明確で低価格な料金体系**
- ✅ **セットアップの簡単さ**（5分で使い始められる）
- ✅ **スマホ最適化**（従業員側のUX重視）

---

## ユーザーペルソナ

### 1. 管理者（雇用主）
- **属性**: 小規模事業者（飲食店、小売店、クリニックなど）
- **スタッフ数**: 5〜50名程度
- **ペイン**:
  - Excelでのシフト管理が煩雑
  - スタッフからのシフト希望収集が大変（LINE、メール、口頭などバラバラ）
  - シフト作成に毎月数時間かかる
  - 既存システムは複雑で高額
- **ゴール**:
  - シフト作成時間を1/3に削減
  - スタッフとのやり取りをシステム内で完結
  - 複雑な操作なしで使える

### 2. スタッフ（非雇用主側）
- **属性**: アルバイト、パート従業員
- **年齢層**: 10代〜60代と幅広い
- **ペイン**:
  - シフト希望の提出方法がわかりにくい
  - 確定シフトの確認が面倒
  - アプリインストールが面倒
- **ゴール**:
  - スマホから簡単にシフト希望を出したい
  - いつでも確定シフトを確認したい
  - アプリなしでブラウザだけで使いたい

## MVPスコープ定義

### Must Have（MVP必須機能）

#### 管理者機能
1. **アカウント登録・ログイン**
   - メールアドレス + パスワード
   - 組織名（店舗名）の登録

2. **スタッフ管理**
   - スタッフの追加（名前、メールアドレス）
   - スタッフ用ログイン情報の発行（ID + パスワード）
   - QRコード生成（スタッフがスマホで読み取ってログイン）
   - スタッフ一覧表示

3. **シフト作成・編集**
   - 月/週単位でのシフト表示（カレンダーUI）
   - 日付をクリックしてスタッフをアサイン
   - 時間帯の設定（例: 9:00-18:00）
   - シフトの編集・削除
   - 下書き保存

4. **シフト希望の確認**
   - スタッフから提出されたシフト希望一覧
   - 希望日をカレンダー上で確認

5. **シフト公開**
   - シフト確定ボタン
   - 公開時にスタッフへ通知（メール）

#### スタッフ機能
1. **ログイン**
   - QRコードスキャン → 自動ログイン
   - または ID + パスワード入力

2. **シフト希望提出**
   - カレンダーUIで日付を選択
   - 「希望する」「希望しない」の2択
   - または「午前のみ」「午後のみ」「終日」の選択
   - 希望時間帯の入力（任意）
   - 提出済み希望の編集・削除

3. **確定シフト閲覧**
   - 自分のシフトのみ表示
   - 月/週単位での表示切替
   - カレンダー形式

4. **通知**
   - シフト確定時のメール通知

#### 共通機能
1. **レスポンシブデザイン**
   - スマホ、タブレット、PCすべてで最適表示

2. **リアルタイム同期**
   - 複数デバイスでの同時利用
   - データの即時反映

---

### Should Have（MVP後の第一優先追加機能）
- スタッフ全員のシフト一覧表示（管理者）
- シフトのCSVエクスポート
- 複数店舗管理
- シフトのコピー機能（前月コピーなど）
- 勤務時間の自動集計

### Could Have（将来的な追加機能）
- プッシュ通知（PWA化）
- シフト提出リマインダー
- スタッフ間でのシフト交換機能
- 勤怠打刻機能
- 給与計算連携

### Won't Have（やらないこと）
- AI自動シフト作成
- 大規模組織向けの複雑な権限管理
- 複雑な勤務形態対応（変形労働時間制など）
- 他システムとの連携（初期は）

## 画面構成

### 管理者側

1. **ログイン/登録画面**
   - シンプルなフォーム（メール + パスワード）

2. **ダッシュボード**
   - 今月のシフト公開状況
   - 未確認のシフト希望件数
   - クイックアクション（スタッフ追加、シフト作成）

3. **スタッフ管理画面**
   - スタッフ一覧テーブル
   - 追加ボタン
   - 各スタッフのQRコード表示/印刷

4. **シフト希望一覧画面**
   - カレンダー形式
   - スタッフごとの希望を色分け表示

5. **シフト作成・編集画面**
   - カレンダー形式
   - ドラッグ&ドロップでアサイン
   - 日付クリックでモーダル表示

6. **シフト公開画面**
   - プレビュー
   - 公開確認

### スタッフ側

1. **ログイン画面**
   - QRスキャン機能
   - または ID + パスワード入力

2. **ダッシュボード**
   - 今月の自分のシフト概要
   - シフト希望提出状況

3. **シフト希望提出画面**
   - カレンダーUI
   - 日付タップで希望入力モーダル

4. **確定シフト閲覧画面**
   - カレンダーUI
   - 自分のシフトのみ表示

## 技術的な検討事項

### QRコードログインの実装方針
1. スタッフ追加時に一意のトークンを生成
2. トークンをQRコードにエンコード
3. QRコードスキャン時にトークンを読み取り
4. トークンでセッション作成

### 通知機能
- MVP: メール通知のみ
- 将来: プッシュ通知（PWA化後）

### データ同期
- Supabase Realtime使用で自動同期

---

## UI/UXの重点ポイント

### デザイン原則
1. **シンプル第一**: 1画面1アクション
2. **視覚的フィードバック**: アクション後すぐに結果表示
3. **エラーの親切さ**: エラーメッセージは具体的な解決策を提示
4. **モバイルファースト**: スマホでの操作を最優先に設計

### カラースキーム
- プライマリ: 青系（信頼感）
- セカンダリ: 緑系（承認・決定）
- アラート: 赤系（エラー・削除）
- ニュートラル: グレー系（背景・枠線）

### タイポグラフィ
- システムフォント使用（読み込み速度優先）
- 大きめのフォントサイズ（視認性重視）

- シフト作成完了率: 80%以上
- NPS（Net Promoter Score）: +30以上

### ユーザビリティ目標
- 管理者の初回シフト作成完了: 15分以内
- スタッフのシフト希望提出: 3分以内
- ページ読み込み時間: 2秒以内
- モバイルでの操作完了率: 95%以上
